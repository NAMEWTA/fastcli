# 运行原件与验收报告

先确定目标项目根。跨 worktree 由负责人提供记录所在的项目根；代码可以在另一个检出，不以命令当前目录、模型位置或技能目录代替它。多机采集先验证参与者可写、负责人可读的实际位置。

## 运行原件不随 Git 提交

要留下的日志、截图、录像、HAR、JSON、覆盖率、状态库、渲染图和工具自动生成的 Markdown，写到项目根 `temp/dev/<change-id>/tasks/<task-stem>/<run-id>/`。`<task-stem>` 是票据文件名去掉 `.md`。Change 的组合运行写 `temp/dev/<change-id>/integration/<run-id>/`；没有所属 Change 的独立检查用 `temp/dev/<主题>/<run-id>/`，不为一次捕获补造 Change。每次运行使用可区分的新目录，并发与复跑不覆盖。仅需看终端结果时不落原件。系统诊断及 Herdr 自身取证使用项目根 `temp/system/`，不因通过 Herdr 启动就把开发测试输出改为系统原件。

安装器为 dev 和 system 补根 `.gitignore` 的 `/temp/`。在 Git 项目留附件前用 `git check-ignore -q -- <目标相对路径>` 确认排除（退出码 0）。可用 `git check-ignore -v -- <目标相对路径>` 查来源，`!` 规则不是排除。用 `git ls-files -- <目标相对路径>` 确认未被跟踪。已跟踪或项目规则未排除时报告冲突，不覆盖、强制添加或擅自改索引。工具需要显式输出路径时传入本轮绝对路径；第三方工具只能在固定目录输出时优先用隔离实例，把需保留的捕获收集到本轮目录，不移动服务原生数据。

只采集必要内容，不记录凭据或无关用户资料。忽略规则不是访问控制、备份或清理许可。跨机器复查需要的原件走已授权的私有共享或制品渠道，不复制进 Git。清理实例后确认必需附件还能打开；到达验收或接手所需期限后只清理本次获准的范围。

确认原型及完整资源、持续维护的测试、夹具、模型和正式发布制品不是运行原件，保留在其权威位置。用于验证这些对象而产生的截图和工具报告仍是运行原件。

## 每张 task 只有一份同名 Markdown 报告

创建 `tasks/01-login.md` 时同时创建 `evidences/01-login.md`，尚未检查就明确写「未验证」。两个目录的普通 `.md` 文件名集合必须完全相同，包括大小写和 `.md` 后缀。`evidences/` 只放这些 Markdown 普通文件，不放索引、子目录、符号链接、截图、额外总结或其他附件。新增、改名或删除 task 时同时处理其报告和引用。不要仅核对数量；`tasks/01-login.md` 对 `evidences/01-login-retry.md` 不合规。

每票由一位写入者更新。失败、阻塞、交接、补测和通过都在同一文件维护；保留影响复查的失败和被后续结果取代的依据。多个方法共用该报告。票据或进展只链接报告，不复制验收正文。没有 task 的小检查直接返回观察或写现有进展，不建孤立的报告。

报告最少包含下列内容。没有事实时明确未验证，不预填「通过」。

```markdown
# 01 登录验收

任务：[01-login](../tasks/01-login.md)
状态：未验证

尚未执行。开始后在本文件记录实际版本、环境、步骤和观察。
```

实际验证后，记录验收项、实际提交或工作树和环境、已执行的命令或用户动作、输入或前置状态、结果及可观察副作用。区分静态证据、运行证据及未验证部分。保留可重跑步骤，用项目根相对路径标注必要的临时原件及本机可用性；无需内嵌整份日志，也不要把本机路径当所有人都能打开的永久链接。需要复查的附件打不开就记录缺口，不据此验收。

例如，`tasks/S2.5-reply-forward.md` 的第一次浏览器走查失败时更新 `evidences/S2.5-reply-forward.md`；修复后仍写这份。两次截图分别留在 `temp/dev/mail/tasks/S2.5-reply-forward/before/` 和 `temp/dev/mail/tasks/S2.5-reply-forward/after/`，并记录各自版本、视口、动作和失败后来如何消失。

可用本包的[只读目录检查](../scripts/check-evidence.mjs)。`SKILL_DIR` 是 `dev-verify` 的目录，`CHANGE_DIR` 是实际 Change 目录：

```sh
node "$SKILL_DIR/scripts/check-evidence.mjs" "$CHANGE_DIR"
```

它只检查同名关系和文件类型，不写文件，也不判断验收结论。没有脚本时直接列出两目录，逐个核对完整文件名和报告类型。

## 完成后才汇总 Change

在实际整合版本通过组合验收，并到达本次约定的交付终点后，Change 负责人写唯一的根 `evidence.md`。记录交付范围、实际版本、组合场景及观察、已接受的限制和各票报告链接。只有本任务要求合并或上线时才以该终点为门禁。

未完成时更新原票报告及已有进展。组合检查尚未通过时在进展记具体阻碍和运行位置，不写冒充完成的总报告。归档保留 Markdown 与正式资产，修复变更资料之间的引用，不将 `temp/` 搬入归档。
