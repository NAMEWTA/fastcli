### 编写或修改技能

**你负责技能的表达方式。**

1. 明确技能要完成的任务、触发条件、输入和产出，核对已有技能与职责边界；本次是通用项目能力时不先提炼个人偏好。使用当前可用的技能编写指南；[本地结构规则](skill-authoring.md)必须满足，不能依赖未安装的宿主技能。
2. 验证技能：frontmatter 含 `name` 和 `description`，引用文件存在，运行必需链接都在本技能包内可解析。
3. 修改确定性工具或结构契约时运行有意义的既有检查，必要时补充针对实际风险的用例。调整触发、路由或读取条件时用代表性自然请求核对选择与实际方法；可逆文字调整不另建只重复正文的机械测试。
4. 交付目标包含 PR 时执行 `dev-deploy`（PR 准备流程），否则按当前授权的提交或交付方式收束。

拿不准某段文字是否有用时，检查它是否改变任务选择、判断或执行。删除无用重复，保留完整方法的条件、例子、反例和边界。告诉它做什么，只有缺少理由会妨碍正确使用时才解释。语气与范围匹配。按 `dev-guardrails` 的适用条件考虑结构化来源，如类型、README、配置；需要判断的经验继续用清楚文字保存。通过本包相对路径读取完整参考；其他技能按需调用。反复遇到却未记录的工作流，先核对已有负责者，再判断是否有独立建立技能的价值。

**回复：** 技能摘要、关键设计决策、验证说明。


文字按`dev-writing`（清晰写作）逐句检查。
