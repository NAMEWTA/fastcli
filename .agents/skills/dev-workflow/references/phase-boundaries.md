# 阶段边界

**阶段**是会话中的一块工作，例如追问、实现、质量检查。定义有意保持模糊：当你觉得“好，这部分完成了”时，一个阶段就结束。

**阶段边界**是两个阶段之间的间隙，也是常规整理上下文的合适位置。阶段中途通常继续，或把剩余工作分给子智能体，避免中途压缩丢掉思路。用户明确要求保存或暂停时，使用 `dev-handoff` 对应方法；保存记录不要求切换上下文或停止工作。

## 五个选项

| 选项 | 作用 |
| --- | --- |
| **继续** | 留在当前会话，完全不切换上下文。 |
| **`清空上下文`** | 清空上下文窗口，从零开始。 |
| **`交接`** | 用 `dev-handoff` 写可移植 Markdown 文件，供新会话或稍后接续；接收者还需能访问引用的产物。 |
| **子智能体** | 把任务送到独立上下文窗口，取得报告。 |
| **`压缩上下文`** | 使用宿主真实提供的压缩能力，以整理后的上下文继续。 |

## 决策树

在边界自上而下判断，第一个**是**决定选择。用户已明确要求保存、交接或暂停时先执行对应意图，不用决策树否定已给出的要求。

**1. 能在当前会话继续吗？** 两种情况会让答案为是：下一阶段需要本阶段作为**一手资料**，或者剩余有效推理上下文足以容纳下一阶段，以实际宿主窗口和当前复杂度为准。追问 → 实现是典型的“是”：实现需要原样推理，而不是推理摘要。继续无成本、无损失，所以先排除它，再考虑其他选项。

**2. 上下文与下一步无关吗？** 会话中的探索、决定和死路是否都可以丢弃？如果可以，选择 **`清空上下文`**。只有宿主提供真实清空能力且相关事实已持久化时才使用。能否恢复旧会话由宿主决定，未核实不能承诺；没有该能力就保存恢复点并继续，不声称已经清空。

判断错的代价是单向的。清掉**相关**上下文，会丢失构建背后的**为什么**，再怎么重读差异也找不回来。

**3. 需要交接或持久恢复点吗？** 以下情况使用 `dev-handoff`：

- 更换**宿主**，例如 Claude → Codex。
- 移到**新目录**或仓库。
- 把工作交给**同事**。
- 在**阶段中途**发现旁支任务，想把它分出去而不中断当前工作。
- 保存当前开发上下文，供**稍后继续**或在会话结束后接续。

`交接` 换来的是**可移植性**和会话之外的恢复记录。如果不需要转移或保存，继续当前会话即可；写好交接文件本身不表示新代理已启动或工作已移交。

**4. 任务可以无人值守吗？** 范围是否足够明确，你离开键盘后也能无须引导地执行？如果是，交给**子智能体**，保留当前会话不动。自动审查是典型例子：智能体阅读差异并报告，过程中不需要你。

**5. 否则，`压缩上下文`。** 上下文相关、宿主相同、目录相同，而且你还需要参与：决策树就在这里落地，并且经常如此。宿主提供压缩能力时，传入下一阶段重点，让摘要保留需要的内容；没有时写简短恢复笔记并继续，不虚构压缩命令。

`压缩上下文` 是**默认落点，不是第一选择**。它放在底部，是因为前四个问题给出的选项都更便宜或更精确。先用它的失败模式是：新会话对某个被摘要压扁的决定自信地理解错了。

## 一手与二手资料

压缩与交接摘要都属于**二手资料**，不能完整替代实际发生的会话及原始产物。交接文档应引用已有规格、决定和证据，接收者按需读取，避免把摘要误当完整事实。主要取舍是：

| 来源 | 信息 | 噪声 | 可用空间 |
| --- | --- | --- | --- |
| 一手，继续 | 完整 | 多 | 少 |
| 二手，`压缩上下文`、`交接` | 有损 | 少 | 多 |

所以第一个问题要先问。只有留在原会话的成本大于收益时，才支付信息损失。

## 这些是判断问题

问题并不客观，每个都包含判断偏好，同一个边界在不同日子可能走不同方向。价值在于**按顺序**询问，常规整理尽量在边界进行；明确保存或暂停的请求按实际意图处理。
