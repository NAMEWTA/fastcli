# 模型检查与状态图

把模型检查结果变成读者可审查的行为图。读者判断规则是否表达了真实意图；检查结果只覆盖声明的模型、假设和边界。

## 选择材料

| 当前需要 | 读取 |
| --- | --- |
| 确认工具、运行命令与依赖 | [本地运行环境](references/runtime.md)、[命令入口](scripts/statechart.mjs) |

## 执行边界

- 输入是 `.tla` 模型及其配置，不接受 JavaScript `.mjs` 模型或其他检查器报告。先核对 Node.js 运行时、Java 与本地 TLC；不把缺少依赖说成规则通过，不为普通解释图自动安装形式化工具。
- 按规则语义区分状态不变量与时序属性，保留进展所需的公平性假设、终态、投影、隐藏迁移、状态上限与未完成检查。不能为了生成更简单的图而隐藏或弱化真实违规。
- 模型描述代码时，把反例逐步回放到真实实现，区分代码缺陷、建模错误和待查反例。没有红色节点不等于系统正确。
- 记录实际命令、工具与模型版本、初始条件、范围、退出结果和证据位置。模型与验证代码保留在项目真实位置；图、工具报告和轨迹写项目根 `temp/dev/`，结论更新 `evidences/` 下与原 task 完全同名的 `.md`。

## 交付

给出图及 Mermaid 文本、每条违规规则及反例、模型省略项、运行完成情况与可重跑命令。区分状态不变量的最短路径与 TLC 提供的时序反例，后者保留循环或停顿，不宣称全局最短。图未覆盖的反例引用原始输出；用户已授权修复时继续完成相应修复与验证。

长期验证包的创建、工具选择和模型漂移维护调用 `dev-formal-verify`，沿用已有模型与代码映射。普通状态讲解由当前学习或设计任务直接绘图，不启动本方法。
