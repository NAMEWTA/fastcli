# 工作树和模拟器清理

1. 快照与审计。记录真实主机、资源池、工作树所在卷与可用空间，例如 Unix 的 `df -Pk <工作树路径>`，或 Windows 的 `Get-PSDrive -PSProvider FileSystem`。沿用原资源记录的计量单位，删除后用仍存在的父目录复测同一卷。运行[本地只读审计](worktree-audit.md)中的 `worktree-audit.mjs`，用 `--base` 指明每组检出的实际直接父分支；父分支不明时先核实，不用默认分支代替。使用 `git worktree list` 的真实路径，因为宿主工作树可能在不同目录中。按大小、年龄、合并状态、未提交工作、PR 状态和明确选择的记录中最近触及它的会话分组。长任务可按实际可用能力后台执行，回读结果后再判断。
2. 分组是建议，不是许可。从用户要求、宿主记录或侧栏核对固定和活跃聊天集合。`safe` 分组仍可能对应用户固定的工作树，因此固定集合优先。主检出、用户保留的检出和手工锁定的工作树保留，不能因已合并就自行解锁或删除。
3. 删除前验证使用情况。对每个 `verify-recent-chat` 行或任何疑点，按现有环境预算安排子智能体读取明确指定的记录，报告聊天是否固定或进行中、触及哪些工作树。审计扇出同样占用 Agent 名额，资源不足时串行。固定聊天通过后台子智能体在兄弟工作树创建方案比选和复现树，即使名称没出现在侧栏，也可能正在使用。核对原任务的负责人、host、会话或服务 ID、进程登记与写入权交回记录；仍有活动写入者或归属不明时保留。
4. 不可逆丢失时暂停。用 `git status --short --untracked-files=all --ignored=matching` 核对跟踪、未跟踪及忽略文件。`wip:N` 是 N 项已跟踪未提交编辑，先展示差异取得决定，因为干净工作树可从分支恢复，未提交内容却会丢失。未跟踪或忽略文件不等于可丢弃内容。逐项核实归属、可再生性与授权，列出文件；不明内容保留。按自主性，干净、已合并、不使用的继续；`wip` 和使用中的暂停。宿主退出可能同时删除工作树时，也须先完成文件、合并和保留条件的核对。
5. 核实交付与进程身份。回读登记路径、分支和当前 HEAD，确认任务完成且写入者已交回。用实际直接父分支的当前引用核对祖先关系，或核对准确匹配本次提交、目标父分支与落地提交的已合并 PR 证据。关闭但未合并、合并后又有新增提交或过期引用都不能证明已交付。核对任务登记的主机、负责人、会话、PID、启动时间、进程组及其成员；PID 复用、进程组混有其他任务或身份字段无法核实时，保留对应进程及其仍可能使用的检出。优先使用宿主会话退出或服务的正常停止入口，等待并确认本任务进程及其子进程退出，再移除目录。活动、固定或归属不明的会话不擅自结束，不使用按进程名匹配的 `pkill`、`killall`。停止失败时保留占用并记录原因。
6. 清理已确认集合。用 `git status --short --untracked-files=all --ignored=matching` 检查文件，再核对锁、使用状态及保存的证据。退出目标目录后，优先使用管理该工作树的宿主清理入口；没有对应入口时，在其他保留检出中按真实路径运行 `git worktree remove <path>`。宿主已移除目录时先回读登记，避免重复删除。命令拒绝时查明原因，保留无法确认可丢弃的文件，不默认使用 `--force`。若另有清除过期登记的任务，先用 `git worktree prune --dry-run --verbose` 核对影响范围。`prune` 只处理失效登记，不会停止进程或删除仍存在的工作树。子分支提交由父分支的合并历史保留。
7. 复测并归还额度。回读 Git 登记、目录、原会话与进程状态，以及同一卷的实际可用空间，记录采样时间。共享缓存和其他任务的占用保留，文件删除后仍被进程打开、远端状态不可读或服务未退出时继续记录未释放项。只归还确认已释放的预留；已有 `.agents/dev/context/environment.md`、等价记录或调度器台账时原处更新，后续容量按实测结果判断。目录估算大小不能替代真实卷空间变化，部分失败也不能归还整项预留。
8. 用户要求释放其他磁盘空间时，再检查模拟器及缓存。先列出测试模拟器，核实无运行任务与需保留状态，只删除本次确认的设备。仅当全部不可用设备都在确认集合中时，使用 `xcrun simctl delete unavailable`；否则按确认的设备 ID 删除。`xcrun simctl runtime list` 后用 `runtime delete <id>` 清确认的旧运行时。需要时再看 Xcode `DerivedData`、`iOS DeviceSupport`、当前开发工具的用户缓存目录中 `state.vscdb.backup` 和 `snapshots/roots/<root>`，以及 pnpm、uv、brew、yarn 包缓存。以曾作为工作区打开的文件夹命名的 root 可能膨胀。按本次授权和实际归属清理，保留共享、使用中或用户要求保留的缓存，不因工作树回收就全局清缓存。清理后同样复测空间。

这是唯一删除用户状态而没有代码审查兜底的手册，因此以上门禁就是审查。

**回复：** 清理前后的卷空间、已删除工作树、已确认退出的任务进程、实际归还的额度，以及每个保留项的一行理由，例如仍有会话使用、停止失败或存在未提交工作。
