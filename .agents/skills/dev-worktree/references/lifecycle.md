# 创建与接手工作树

1. 用 `git worktree list --porcelain -z` 读取实际登记，辨别主检出、目标父分支及已在使用的检出。用完整分支引用和 `git rev-parse --verify "<引用>^{commit}"` 核对父提交。已选基线、分支名或尚有归属疑问的改动先查清。各工作树有独立工作目录和索引，分支引用由同一仓库共享。
2. 在主检出的 `.agents/dev/worktree/<任务名>/` 选定新路径，即使调用来自另一工作树。使用能对应现有任务的合法单段目录名，核对实际文件系统中的重名、保留名、占用和链接跳转。安装 dev 技能会在项目根补齐 `/.agents/dev/worktree/`。用 `git check-ignore` 验证目标确实已忽略，并用 `git ls-files -- .agents/dev/worktree` 检查是否误跟踪。规则不生效或已有跟踪内容时，先修正授权范围内的配置或报告阻塞。
3. 创建前复用 `.agents/dev/context/environment.md` 或已有权威位置中适用的记录，多个检出引用同一位置。预算缺失、主机变化或观测失效时，直接核对目标主机的运行环境、有效 CPU、可用内存、目标卷剩余空间与已有预留。由同一负责人预留工作树增量及初始化、运行负载，并为后续集成留出余量；名额不足或关键容量无法确认时排队，先沿用现有检出做可独立完成的轻量工作。额外集成树与已有闲置树也计入预算。
4. 确认任务分支名未被占用且已取得预留后，用 `git -C "<主检出>" worktree add -b "<任务分支>" "<绝对路径>" "<基线SHA>"` 创建。重新读取实际分支、HEAD 和登记路径。接手续作时读取已有工作树和未提交状态；身份相符就沿用，遇到路径或分支冲突保留旧检出，核实后为新任务分配唯一名称。
5. 初始化前核对目标主机的运行环境与本次预留，按项目规则初始化依赖、端口、测试数据和必要配置。安装、构建及测试的内部 worker 沿用同一预算。只读取并复制明确需要且有授权的本地文件。工作树与原检出共享的外部资源仍需隔离，由 `dev-guardrails` 的共享状态隔离方法处理。
6. 在原任务记录负责人、主机与资源池、宿主会话或服务 ID，以及本任务启动进程的 PID、启动时间、进程组和停止入口。交接提供仓库、绝对路径、任务分支、直接父分支、原基线、HEAD、变更范围、已完成的检查及未提交内容。采用宿主已有的 detached HEAD 时，先用明确的任务分支保留提交，再用于交付和清理。缺少可用主检出或写入权限时说明实际阻塞。

已选任务结束后按[父分支集成](parent-merge.md)回收，单独清理按[工作树清理](worktree-cleanup.md)核对候选。
