# 交接方法

编写一份总结当前对话的交接文档，让一个全新的代理可以继续工作。使用[交接模板](../assets/handoff.md)，统一保存到 `.agents/dev/changes/<日期-主题>/handoff.md`，沿用已有任务的真实位置。不把项目进度写入技能安装目录。

在文档中加入“建议使用的技能”一节，列出下个代理应该优先读取哪些 dev 方法或已安装的 dev 技能。按宿主实际可用能力调用，缺少调用工具时直接读取已安装入口；未安装的可选技能不得成为恢复阻塞，不需要额外技能时明确说明。

不要重复其他产物已经记录的内容，例如规格、计划、ADR、问题、提交和差异。使用实际存在的项目路径或已核实的任务地址引用它们，并简要说明接收者需要读取什么。

写明本任务资源预留、执行主机和采样时间，已有环境记录时直接引用。仍运行的实例保留可核对身份、所属任务、工作目录与退出状态；恢复方法负责重查当前可用量，交接文档不另存一份并发预算。

有确认原型时，引用 HTML 入口及本地资源、版本/内容指纹、确认记录和范围、本次页面/状态定位；跨机器交接保留同一资源，未确认或内容已变的部分写明。不要仅留下临时预览 URL，也不把前任报告转换成用户确认。

对 API 密钥、密码、个人身份信息等敏感内容进行脱敏。

如果用户传入参数，将其视为下个会话的重点描述，并据此调整文档。把“下一会话重点”写入文件；没有另行指定时沿用当前任务的剩余目标。
