### 会话接续

**你负责恢复点。读前任轨迹，不重做。**

1. 定位前任轨迹。先读当前任务的交接文档，以及它引用的规格、计划、决定和证据；也可使用用户或宿主已提供的相关记录、云智能体地址、已推送分支。不要跨工作区搜索其他项目私人聊天。先读概览和最后消息，再向前扫描决策点；长记录先按问题分段读取，完成下一步资源核对并取得预留后，在实际有子智能体能力时可交其解析，主线程保留压缩时间线。按任务需要和实际工具能力分工。
2. 重建操作状态。确认工作目录、分支与工作树，查看已落地内容（`git status`、`git log`、对基础分支的 `git diff`）、开放待办、已有决策和未提交修改。前任轨迹是恢复起点，保留已作决定及理由；与当前代码、提交或服务矛盾时，以可核对的最新事实更新现状，不重复已充分证实的工作。原始目标和完成条件仍是期望，不能因现有代码缩小剩余范围。
   启动代理、构建或其他负载前，核对交接中的执行主机、未退出实例身份和资源预留；已有 `.agents/dev/context/environment.md` 或等价记录时复用有效部分，缺失或过期的条件按当前主机补查。旧 PID 先核对启动时间或实例身份，旧可用量不能直接转成新名额；跨机器使用目标主机实测值。保留仍活动或归属不明的占用，只有核实已经结束的部分才返还预留。
   存在确认原型时，检查接收到的 HTML/CSS/JS/资产是否对应确认版本或内容指纹，读取用户确认的来源与范围；缺文件、内容漂移和未确认场景分别说明，只让受影响部分返回 `dev-prototype`，不能从前任自报完成推断用户已认可。
3. 比较完成与待办。对照计划和交付，指出恢复点，不重跑前任复现、不重做已完成工作。只有具体证据已变化或出现矛盾时才扩大复核，不从零重跑所有工作。
4. 把剩余工作路由到匹配的 dev 方法，选择结论：继续执行、交付完成的建议、认可或推翻前结论、复盘失败执行。接续手册在此结束，其余由相应执行方法负责；沿用已有任务与授权，不重开已完成阶段。未安装可选技能时按现有工具能力继续。
5. 在真实产物上按原始目标验证继承主张。先核对已有检查对应的版本、范围和实际结果，再对影响接续的关键状态作必要验证；前任自报通过不是证据，未验证事项继续明确标注。只围绕剩余风险补验证，不因交接重跑全部测试。

**回复：** 前任停在哪里，继承和重做了什么（理想情况没有重做），恢复点和结果。
