# 开发环境与资源配置

交付有时间、执行位置、事实来源和适用负载的环境记录，说明现在可以启动哪些工作、最多同时运行多少，以及何时应排队或重测。用户已经指定的主机、范围和上限继续适用；记录文件本身不提供后台调度或操作系统隔离。

## 核对环境与容量

每次执行环境接入或容量评估分支，都读取[主机资源与准入方法](references/host-resources.md)，检查当前执行宿主。远端只检查用户指定且已有访问能力的主机；不可达或身份不明的目标不计入可用容量。

1. 从项目指令、依赖清单、锁文件、版本文件和实际检查入口取得运行要求，逐主机、逐目标检出核对版本与能力；区分满足、缺失、不兼容和未核实。宿主工具适配按 `dev-help` 处理。
2. 读取有效 CPU、可用内存与压力、实际文件系统剩余空间、存量 worktree 和相关进程；容器或虚拟机同时核对可见的配额与共享资源池，不能把整机总量当作任务可用量。
3. 复用当前负载的测量或在余量允许时做单项校准，计入 Agent 及其安装、构建、测试、浏览器等子进程和磁盘增长。分别给出会话、重任务、保留工作树的上限及当前可新增量；三者共用预算，未知不等于无限，新增量可以为 `0`。
4. 由同一负责人或已有调度器维护预留，派发前复测并分批启动。跨 Change、嵌套 Agent 和共享磁盘不能重复分配同一份余量。暂停、恢复、压力事件与回收后按完整方法更新。
5. 发现已完成且已合并到直接父分支的回收候选时，调用 `dev-worktree` 的现有审计与清理方法，传入主机、任务归属、合并证据和进程身份。核实实际释放后更新预算；本技能不维护第二套删除流程。
6. 在预算内验证最小工作链路。项目缺少行为验证时按当前授权调用 `dev-verify`；需要形式化能力时读[接入前提](references/formal-options.md)，专门方法仍由 `dev-formal-verify` 负责。需要离线持续运行时，再按 `dev-help` 核对真实唤醒机制。

## 按需保存团队配置

只有用户要求创建、修改或整理团队配置时，读取[团队配置方法](references/configure-team.md)，使用[团队模板](assets/team.md)保存到 `.agents/dev/context/team/<team_name>.md`。未指定名称时从 topic 生成可辨识且不覆盖其他团队的名称。多个文件独立存在，由用户在任务中显式引用具体文件；普通环境初始化不创建默认团队，不扫描或合并团队规则，也不向根项目指令注入自动加载入口。

仅编辑团队文档时不启动环境探测或任务。只保存文件不宣称改变了宿主参数。

## 报告来源与监控

用户要求接入聊天、工单、邮件、监控告警，或按来源自动发现需求时，可选用 `dev-issue-setup` 完成来源、追踪器、仓库路由和触发器初始化。调用时传入真实连接器、已有授权、触发与失败恢复要求，交付可用配置，不假定后台服务存在。

来源平台不决定代码仓库或问题追踪器。手工单次任务不要求启用监控；定时、事件或 webhook 方式必须对应宿主中实际创建并验证的触发机制。新增来源与触发配置存入 `.agents/dev/project/issue-automation/`，秘密只保留安全引用。

## 输出与持久化

按当前任务读取 `.agents/dev/AGENTS.md` 和相关子目录说明，不假定宿主会递归自动加载。默认持久化骨架由安装器在选中 dev 技能时补齐，不属于本技能的执行步骤；本技能不维护骨架模板或初始化脚本。业务记录仍按真实内容创建。

环境与资源事实使用[环境记录模板](assets/environment.md)，默认保存于 `.agents/dev/context/environment.md`；已有等价记录原地维护。独立 worktree 和子任务引用负责人给出的同一实际位置，不各写一份全机额度。存在原生调度器时记录其权威预算入口，不复制易漂移的并发台账。只保存必要摘要，秘密仅留安全引用，运行原件留项目根 `temp/dev/`。

交付各主机环境结论、预算及计算依据、正在占用的预留、排队或阻塞项、回收结果和重测条件。区分建议上限与实际生效的运行时限制；未经验证的远端、配额或新会话能力保留未知，不承诺仅凭技能文档就绝不会 OOM。
