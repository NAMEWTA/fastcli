# 本地 Markdown 工作记录

新增事项和规格统一以 Markdown 文件存放在 `.agents/dev/changes/`，已有记录按真实位置查阅引用；技能自身目录只存方法，不写项目工作数据。

## 约定

- 每个功能一个目录：`.agents/dev/changes/<YYYY-MM-DD-slug>/`
- 每个变更只有一份权威行为契约，沿用已有 brief、spec、事项或设计章节；缺少合适记录且确需独立规格时，默认使用 `.agents/dev/changes/<YYYY-MM-DD-slug>/spec.md`。文件名不决定是否已具备实施条件，不重复维护 brief/spec 正文。
- 每张实施票保存一个 `tasks/<NN>-<slug>.md`，新组从 `01` 开始，并同时保存 `evidences/` 内完全同名的一份 Markdown，未执行标「未验证」。加票、改名或删除时同步调整该票报告和引用。两个目录的普通 `.md` 文件名集合（含大小写）必须相同；`evidences/` 不放其他 Markdown、附件、链接或子目录。失败、阻塞和复验均更新原报告。保存票据与报告后在同一 Change 的 `plan.md` 汇总 DAG、共享上下文与整合安排，单票也有计划。
- 验证原件放项目根 `temp/dev/`。完成组合验收并达到交付终点后，负责人在 Change 根写唯一的 `evidence.md`。取证方法见 `dev-verify`（证据存放）；单装本技能时直接核对票据与报告名，不依赖其他技能或脚本。
- 当前进展选择一个权威位置：沿用原票或已有 `progress.md`。计划的接续点链接该记录，并指向当前前沿及下一项动作。
- 进展说明实际已完成与已验证的范围、证据和版本、剩余部分、当前阻塞与下一步。前置产物可用才写可实施；本机实现、整合通过和发布完成按实际证据分别说明，不预填通过。
- 规划跨轮时写明已拆到哪项要求、下一项待核对什么；计划就绪而尚未实施时写明首个可开工切片。实施中每取得可复用的结果、发生阻塞或准备交接，就更新当前切片编号、片内最后核实的结果及证据、下一项具体动作。片内中断也能从该动作继续。并行时逐项标出仍在进行的切片。恢复后先核对相应工作树或产物，再从尚未完成的动作接续。
- 评论和对话历史追加在文件底部的 `## 讨论记录` 标题下；过期结论留作历史并注明被什么替代，不与顶部当前状态并列。恢复时核对实际代码和证据，沿用仍有效结果，不重做已有工作。

## 接续旧计划

只读检查按原路径读取旧表格和接续点，已有实施授权可按当时有效的契约接续。用户要求修订旧计划时，将原计划中的实施切片提取为独立票据，沿用现有票据、稳定标识、有效引用和证据。若旧表格维护实际进展，把进展转入对应票据，或引用既有 `progress.md`；在原计划位置更新索引。写入中断后核对已保存的文件，补齐缺项。没有写入条件时，返回逐文件命名的完整草稿和具体阻塞。

## 外部事项

确有授权时，由 `dev-issue` 在 GitHub 发布或维护可认领正文，指向接手者可访问的本地票据与计划版本。正文包含必要背景、交付与验收，并注明权威来源和发布基线；仅列本机绝对路径不能作为交接。资料尚不可共享时，提供必要原文并说明未共享部分。

独立票据继续维护实施契约与直接依赖，进展沿用原票或已有 `progress.md`。Issue 展示对应版本的内容，不另维护一组独立更新的任务、阻塞边或进展。远端讨论产生已采纳的新决定时，在授权范围回写权威记录，再更新发布正文；无法同步时明确待同步及其影响，不能将两份冲突内容同时标为当前契约。接续时核对源版本和实际产物。

尚未建立本地票据、仅要求撰写 Issue 时，事项正文可以承担权威行为契约，无需为发表 Issue 自动建立整套本地计划。后续明确调用本技能时，复用该契约形成本地实施票据，并标明各记录的职责。改变既有权威位置须有明确决定，保留有效标识、完成证据及入链。

## 当技能要求“获取相关任务”

读取引用路径处的文件。用户通常会直接提供路径或事项编号。

## 探路操作

供大型需求的决策地图使用。**地图**是一个文件，每项探索问题对应一个**子文件**。问题解决后如需实施计划，依据已确认结论单独生成实施票据，再组装计划。

- **地图**：`.agents/dev/changes/<YYYY-MM-DD-slug>/map.md`，正文由笔记、目前决定和迷雾组成。
- **子任务**：`.agents/dev/changes/<YYYY-MM-DD-slug>/questions/NN-<slug>.md`，从 `01` 开始编号，正文写问题。用普通文字记录工作方式：研究、原型、访谈或前置操作；并记录负责人、当前进展和答案位置，不要求固定字段。
- **阻塞关系**：顶部附近的一行 `依赖：NN, NN`。当列出的所有前置问题都有可核对的答案时，解除阻塞。
- **前沿**：扫描 `.agents/dev/changes/<YYYY-MM-DD-slug>/questions/`，寻找开放、未被阻塞且未被认领的文件；编号最小者优先。
- **认领**：并行工作时由协调者分配唯一负责人，每人只写分配的问题和研究文件，地图与共享进度由协调者更新；已有跟踪器按其认领机制执行。单人工作无需额外锁或状态系统。
- **解决**：在 `## 答案` 下追加已证实答案、理由和来源，把进展记为已解决，再把上下文指针——要点加链接——追加到 `map.md` 的目前决定。调用 `dev-grill`、研究或原型方法时传入该答案位置，被调用者写回此处或返回由唯一负责人合入；不同时建立第二份决策正文。规格引用已定结论，必要时更新相关行为条款。
