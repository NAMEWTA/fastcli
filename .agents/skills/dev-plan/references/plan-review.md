# 交付计划前核对

在[切片方法](vertical-slicing.md)的粒度与阻塞核对，以及[多阶段计划](multiphase-plan.md)的计划检查步骤中使用。核对现有计划与模板，不增加审批阶段、固定字段或另一份任务清单。小计划可直接逐项检查，复杂计划按任务检查并修正原文。

## 切片与阻塞

1. **交付与粒度。** 每项说明用户或调用者完成的一个行为，能在前置产物可用后独立演示或验证，大小适合一个全新上下文。一个工作包若包含多个可分别验收的行为，继续拆分；公共契约任务应有调用者和自己的验证入口。
2. **真实依赖。** 每条阻塞指出所需产物或决定，而非只列编号。分别核对下游开工与最终联验各需什么。若稳定契约与样例已足以开工，两端即可各自实现并验证；双方真实实现只阻塞消费它们的联验。读到的接口、组件、测试夹具与验收场景也要与依赖核对，避免漏掉隐含前提。没有阻塞的项才能进入当前前沿。发现循环时检查是否把共同前提与各自功能混在同一任务里，修正边界后再接线。
3. **验收完整。** 把每项承诺与验收逐一对应。若交付同时包含导出和导入，不能只凭导出测试通过便完成整项。引用规格中的验收时标明本项承担哪部分；完整跨任务场景由明确的整合任务负责。本项不能等待尚未声明的未来工作才通过自己的完成条件。

广泛机械重构沿用切片方法中的例外：说明哪些中间点允许暂时不可运行，最终整合点验证什么，不把这些中间点当作已交付功能。

## 核对票据与 DAG

1. 打开本次交付范围内的票据文件，核对标识唯一、每张票在计划中恰有一行、每行能打开对应的票。以票内记录为准，逐条核对直接依赖的链接与必需产物。修复缺失引用、重复节点、重复依赖或自依赖。跨 Change 的外部产物核对实际位置及解除条件，不计入当前 DAG。
2. 用票据建立待检查集合。反复移除所有在集合内没有前置的票据，再从剩余票据的待检查边中去掉指向已移除票据的边。集合清空表明没有循环。若集合仍有票且无项可移除，沿剩余依赖追到重复票据，重新核对共同前置与切片边界，修正后重查。该步骤只核对图结构。
3. 按当前工作树或可访问交付物核对开工前沿。对每张未完成的票，检查所有必需产物是否已经可用，再核对写入边界、共享资源和整合安排。计划引用实际进度记录和下一项动作；修订依赖时先改票，再同步计划。

## 从规格反查覆盖与协作

从原始目标、规格和用户明确的数量逐项寻找实现与验证归属；小需求直接核对，多切片按需使用[规格覆盖表](plan-template.md#规格覆盖)。再按[规格覆盖](plan-template.md#规格覆盖)从每个切片反查本次请求，移出无关工作。修复遗漏或重复责任，明确接口两端、真实生产消费者、配置、示例、文档和适用回归由谁承接。跨切片场景有整合责任，但不因此把每种检查单独拆票；全部任务完成也不能直接推导整体目标完成。

并行候选除了可写路径，还要核对共享 API、数据模型、迁移顺序、注册点与测试资源。不同文件或独立工作区不自动消除语义冲突；安排共享对象的唯一负责人和必要顺序，不把普通人员交接伪装成依赖。

## 构建、可见结果与证据

4. **实施导航。** 对照[单个切片](plan-template.md#单个切片)，跨阶段时再对照完整模板的“文件”“构建”“可见结果”：已有路径、符号和命令已经核实；新增文件、测试或命令明确写为计划创建。先核实影响产品行为、外部调用方式、范围、验收或数据语义的决定再出具新票。记录仍需解决的选择、受影响范围与解除条件，已有独立票据在原授权下接续。迁移、安全与不可逆操作按实际风险补齐必要顺序、恢复和停止条件。
5. **证明完成。** 每个验收都有条件、动作、可观察结果和证据入口，命令注明运行位置与必要环境、输入。逐名核对 `tasks/` 与 `evidences/` 的 `.md` 一一对应，后者没有其他文件、链接或子目录，未验证不预填通过。按风险检查正常、失败和回归，说明单元检查、真实入口或性能测量各证明什么，不强制固定条数；不适用的验证维度说明原因。需要的环境不可用时记录缺口，不能用构建成功、代理报告或计划中的预期结果当作通过证据。有已确认设计或原型时，任务能定位资源版本/指纹、真实用户确认范围、页面、状态与适用源码，安排相同状态、主题和视口的实际核对，不能只给设计摘要。需要确认却尚未取得、或资源已改变的部分，按真实依赖限制实施，不能以任务勾完替代体验确认。实现、集成和发布的完成条件分别对应其实际交付点。
6. **接手与一致性。** 新会话只凭任务、可读来源和当前代码即可知道为什么做、本项范围、已定约束、前置产物和如何验证，不依赖原对话。指针不能访问时提供必要原文；必需方法随任务传递，不要求全量技能扫描。当前进展只有一个权威位置，说明已验证内容、剩余部分与下一步；历史不覆盖现状。计划索引与任务正文中的依赖、范围和授权一致，不复制正文建立竞争记录。来源、基线、设计、接口、配置或输入变化时核对受影响证据，不能沿用失效结论，也不重跑无关阶段。

## 核对后交付

先修正对应票据，再更新计划汇总。向用户给出计划和票据链接、可开工项、整合验收与核对限制。只要求计划就在这里结束；已有持续实施授权则携带这些资料交给 `dev-build`。核对本身不证明计划中的功能已经实现。
